# Sync V2, fase 1 — reparo e prova Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fazer a entidade que chegou e não virou linha ser reparada sozinha, e dar aos três aparelhos uma prova de que têm o mesmo conteúdo — contagem e hash por família, comparados no hub e mostrados na tela.

**Architecture:** A fila de pendentes sai da memória e vira tabela, com uma varredura de reparo na abertura que compara `sync_state` com as tabelas de domínio. O manifesto é calculado a partir de `sync_state` (que já é sombra completa de tudo que sincroniza, inclusive do que nasce local — ver `sync_emit.rs:120`), viaja junto com a batida do aparelho, e o hub guarda por dispositivo. Nada do estado canônico entra nesta fase.

**Tech Stack:** Rust (rusqlite, axum 0.8, sha2 — já presente em `mos-storage-sqlite`), React 19 + TypeScript no desktop. Nenhuma dependência nova.

**Spec:** `docs/superpowers/specs/2026-09-04-sync-v2-design.md` — esta fase implementa as seções **4 (pendentes e reparo)** e **5 (manifesto)**, mais a correção documental. As seções 1, 2, 3 e 6 (estado canônico, revisão-base, `aplicado_ate`, snapshot) e a migração ficam para a fase 2, que terá plano próprio.

## Global Constraints

- **O M/OS continua funcionando com a VPS fora do ar.** Nada aqui pode fazer abertura ou escrita local dependerem de rede.
- **Nenhuma dependência nova** em nenhum crate nem no `package.json`.
- **O hub não ganha domínio.** Ele guarda o que o aparelho diz de si — inclusive o manifesto — e devolve; não interpreta, não recusa, não decide.
- **Falha de rede não interrompe trabalho local.** Manifesto que não sobe vira log, não erro de tela.
- **O hash é sobre `sync_state`, nunca sobre as tabelas de domínio.** As tabelas carregam `updated_at` local (a projeção carimba a hora de quem aplicou), então o mesmo conteúdo produz bytes diferentes em cada aparelho. `sync_state` guarda campo e instante HLC, que são idênticos depois da convergência.
- `cargo fmt --all` e `cargo clippy --workspace --all-targets -- -D warnings` limpos; `npm run build` no desktop (é ele que confere tipo dentro de teste, e não o `typecheck`).
- Comentários e nomes em português. Comentário explica **por quê**.

```sql
--
-- # Por que ela precisa existir no BANCO
--
-- Ela era um `Vec` em memoria dentro da projecao. O caminho do estrago:
-- a entidade chega, o estado e gravado em `sync_state`, a materializacao falha
-- (chave estrangeira cujo pai ainda nao chegou), a entidade entra na lista, o
-- cursor avanca no mesmo pull, e o app fecha. Na abertura seguinte a lista
-- nasce vazia e ninguem tenta de novo — a entidade fica viva no banco de
-- sincronizacao e invisivel na tela, para sempre.
--
-- Nao e hipotese: `sync_projecao.rs` guardava `pendentes: Vec<(String, Uuid)>`,
-- e `engine.rs` grava o cursor quando a rodada nao tem erro — e falha de
-- materializacao nao marca erro ali.
--
-- # Por que ela nao precisa viajar
--
-- Ela descreve o que ESTA maquina ainda nao conseguiu materializar. Replicada,
-- faria um PC tentar consertar o que o outro nem tem. Fica em `LOCAIS`.
CREATE TABLE sync_pendentes (
    entity_kind   TEXT NOT NULL,
    entity_id     TEXT NOT NULL,
    tentativas    INTEGER NOT NULL DEFAULT 0,
    ultimo_erro   TEXT NOT NULL DEFAULT '',
    atualizado_em TEXT NOT NULL,
    PRIMARY KEY (entity_kind, entity_id)
) STRICT;

PRAGMA user_version = 38;
```

```rust
    ///
    /// `tentativas` sobe a cada passagem: e o numero que separa "acabou de
    /// chegar fora de ordem" de "esta encalhada ha dias", e sem ele o reparo

    pub(crate) fn marcar_pendente(
        transacao: &Connection,
        kind: &str,
        id: uuid::Uuid,
        erro: &str,
    ) -> Result<(), CoreError> {
        let agora = crate::repository::format_time(time::OffsetDateTime::now_utc())?;
        transacao
            .execute(
                "INSERT INTO sync_pendentes (entity_kind, entity_id, tentativas, ultimo_erro, atualizado_em) \
                 VALUES (?1, ?2, 1, ?3, ?4) \
                 ON CONFLICT(entity_kind, entity_id) DO UPDATE SET \
                 tentativas = tentativas + 1, ultimo_erro = ?3, atualizado_em = ?4",
                rusqlite::params![kind, id.to_string(), erro, agora],
            )
            .map_err(map_sql_error)?;
        Ok(())
    }

    /// Tira a entidade da fila — ela virou linha.
    pub(crate) fn limpar_pendente(
        transacao: &Connection,
        kind: &str,
        id: uuid::Uuid,
    ) -> Result<(), CoreError> {
        transacao
            .execute(
                "DELETE FROM sync_pendentes WHERE entity_kind = ?1 AND entity_id = ?2",
                rusqlite::params![kind, id.to_string()],
            )
            .map_err(map_sql_error)?;
        Ok(())

    /// O que esta na fila agora.
    pub(crate) fn pendentes_guardados(
        conexao: &Connection,
    ) -> Result<Vec<(String, uuid::Uuid)>, CoreError> {
        let mut consulta = conexao
            .prepare("SELECT entity_kind, entity_id FROM sync_pendentes ORDER BY atualizado_em")
            .map_err(map_sql_error)?;
        let linhas = consulta
            .query_map([], |linha| {
                Ok((linha.get::<_, String>(0)?, linha.get::<_, String>(1)?))
            })
            .map_err(map_sql_error)?;
        let mut fila = Vec::new();
        for linha in linhas {
            let (kind, id) = linha.map_err(map_sql_error)?;
            if let Ok(id) = uuid::Uuid::parse_str(&id) {
                fila.push((kind, id));
            }
        }
        Ok(fila)
    }
```

```rust
//! A varredura que faz aparecer o que chegou e nao apareceu.
//!
//! # Por que ela existe
//!
//! `sync_state` e a sombra de tudo que sincroniza — inclusive do que nasce
//! local, porque `emitir` chama `absorver_local` na mesma transacao. Entao uma
//! entidade que esta na sombra e nao esta na tabela de dominio significa uma
//! coisa so: ela chegou e nao virou linha.
//!
//! Isso acontecia e ninguem via: a fila de pendentes era memoria, o cursor
//! avancava assim mesmo, e a proxima abertura nao sabia que havia o que
//! consertar. A varredura fecha o buraco olhando o banco, e nao a fila — e por
//! isso ela conserta tambem os bancos que ja estao nesse estado.
//!
//! Ela roda na ABERTURA. Rodar a cada rodada custaria uma varredura por
//! sincronizacao para achar, quase sempre, nada.

use mos_core::CoreError;
use serde::Serialize;

use crate::{map_sql_error, SqliteStorage};

/// O que a varredura encontrou.
#[derive(Debug, Default, Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct Reparo {
    /// Entidades na sombra que nao tinham linha.
    pub examinadas: usize,
    /// Quantas viraram linha agora.
    pub reparadas: usize,
    /// As que continuaram sem virar, com o motivo. Elas dependem de algo que
    /// nao chegou — e a mensagem e o que permite descobrir o que.
    pub falharam: Vec<String>,
}

impl SqliteStorage {
    /// Materializa o que esta na sombra e nao esta na tabela.
    pub fn reparar_materializacao(&self) -> Result<Reparo, CoreError> {
        let mut reparo = Reparo::default();

        // A lista de candidatos sai de uma consulta so, e nao de uma varredura
        // por tabela: `sync_state` ja diz kind e id, e o mapa diz em que tabela
        // aquele kind vira linha.
        let candidatos: Vec<(String, uuid::Uuid)> = {
            let conexao = self.connection.lock().map_err(crate::map_lock_error)?;
            let mut consulta = conexao
                .prepare("SELECT entity_kind, entity_id FROM sync_state")
                .map_err(map_sql_error)?;
            let linhas = consulta
                .query_map([], |linha| {
                    Ok((linha.get::<_, String>(0)?, linha.get::<_, String>(1)?))
                })
                .map_err(map_sql_error)?;
            let mut candidatos = Vec::new();
            for linha in linhas {
                let (kind, id) = linha.map_err(map_sql_error)?;
                let Ok(id) = uuid::Uuid::parse_str(&id) else {
                    continue;
                };
                let Some(mapa) = crate::sync_projecao::mapa_de(&kind) else {
                    // Tipo que este binario nao conhece: guardado, e nao
                    // materializavel. Nao e defeito — e o cliente antigo
                    // recebendo o que o novo mandou.
                    continue;
                };
                let existe: bool = conexao
                    .query_row(
                        &format!(
                            "SELECT EXISTS(SELECT 1 FROM {} WHERE {} = ?1)",
                            mapa.tabela, mapa.chave
                        ),
                        rusqlite::params![id.to_string()],
                        |linha| linha.get(0),
                    )
                    .unwrap_or(false);
                if !existe {
                    candidatos.push((kind, id));
                }
            }
            candidatos
        };

        reparo.examinadas = candidatos.len();
        if candidatos.is_empty() {
            return Ok(reparo);
        }

        // Varias passadas, porque a dependencia pode estar entre os proprios
        // candidatos: a hora precisa do projeto, e os dois podem ter sumido.
        // Para quando uma passada inteira nao consegue nada.
        //
        // A mensagem do erro fica FORA da fila e so entra em `falharam`, no fim:
        // guardada na fila, ela seria comparada a cada volta e faria duas
        // tentativas do mesmo item parecerem itens diferentes.
        let mut fila = candidatos;
        let mut ultimo_erro: Vec<(String, uuid::Uuid, String)> = Vec::new();
        loop {
            let tentativa = std::mem::take(&mut fila);
            let antes = tentativa.len();
            ultimo_erro.clear();
            for (kind, id) in tentativa {
                match self.materializar_por_reparo(&kind, id) {
                    Ok(()) => {
                        reparo.reparadas += 1;
                        let conexao = self.escrita()?;
                        SqliteStorage::limpar_pendente(&conexao, &kind, id)?;
                    }
                    Err(causa) => {
                        ultimo_erro.push((kind.clone(), id, causa.message));
                        fila.push((kind, id));
                    }
                }
            }
            if fila.len() == antes || fila.is_empty() {
                break;
            }
        }

        reparo.falharam = ultimo_erro
            .into_iter()
            .map(|(kind, id, motivo)| format!("{kind} {id}: {motivo}"))
            .collect();
        Ok(reparo)
    }
}
```

`materializar_por_reparo` é um método novo e curto, ao lado de `materializar_um` em `sync_projecao.rs`, que expõe a materialização para fora da projeção:

```rust
    /// Materializa uma entidade a partir do estado ja guardado.
    ///
    /// Existe separado de `materializar_um` porque aquele e privado da rodada e
    /// assume a projecao viva. O reparo roda sem rodada nenhuma.
    pub(crate) fn materializar_por_reparo(
        &self,
        kind: &str,
        id: uuid::Uuid,
    ) -> Result<(), CoreError> {
        let mut projecao = ProjecaoSqlite::nova(self);
        projecao.materializar_um(kind, id)
    }
```

Declarar o módulo em `lib.rs`, junto dos outros: `mod sync_reparo;` e `pub use sync_reparo::Reparo;`.

```rust
//! O manifesto: o que este aparelho tem, em contagem e hash.
//!
//! # Por que sobre `sync_state`, e nao sobre as tabelas
//!
//! A projecao carimba `updated_at` com a hora de quem aplicou. Dois aparelhos
//! com exatamente o mesmo conteudo tem bytes diferentes nas tabelas de dominio,
//! e um hash calculado ali acusaria divergencia onde nao ha nenhuma.
//!
//! `sync_state` guarda campo, valor e instante HLC — e o instante e o MESMO nos
//! dois lados depois da convergencia, porque ele nasce no aparelho que
//! escreveu. E o unico lugar do banco onde "mesmo conteudo" e "mesmos bytes".
//!
//! # O que ele nao prova
//!
//! Que a entidade aparece na tela. Sombra igual e tabela vazia e exatamente o
//! defeito que a varredura de reparo conserta — por isso as duas coisas vivem
//! juntas nesta fase.

use mos_core::CoreError;
use serde::Serialize;
use sha2::{Digest, Sha256};

use crate::{map_sql_error, SqliteStorage};

/// Uma familia no manifesto.
#[derive(Debug, Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct LinhaDoManifesto {
    pub familia: String,
    pub contagem: usize,
    /// SHA-256 dos pares `(id, estado)` ordenados por id, em hexadecimal.
    pub hash: String,
}

impl SqliteStorage {
    /// O retrato deste aparelho, por familia.
    ///
    /// Ordenado por id dentro de cada familia: sem ordem estavel, o mesmo
    /// conteudo daria hashes diferentes conforme o SQLite devolvesse as linhas.
    pub fn manifesto(&self) -> Result<Vec<LinhaDoManifesto>, CoreError> {
        let conexao = self.connection.lock().map_err(crate::map_lock_error)?;
        let mut consulta = conexao
            .prepare(
                "SELECT entity_kind, entity_id, estado FROM sync_state \
                 ORDER BY entity_kind, entity_id",
            )
            .map_err(map_sql_error)?;
        let linhas = consulta
            .query_map([], |linha| {
                Ok((
                    linha.get::<_, String>(0)?,
                    linha.get::<_, String>(1)?,
                    linha.get::<_, String>(2)?,
                ))
            })
            .map_err(map_sql_error)?;

        let mut familias: Vec<LinhaDoManifesto> = Vec::new();
        let mut atual: Option<(String, usize, Sha256)> = None;
        for linha in linhas {
            let (kind, id, estado) = linha.map_err(map_sql_error)?;
            let precisa_trocar = atual.as_ref().map(|(k, _, _)| k != &kind).unwrap_or(true);
            if precisa_trocar {
                if let Some((familia, contagem, hasher)) = atual.take() {
                    familias.push(LinhaDoManifesto {
                        familia,
                        contagem,
                        hash: format!("{:x}", hasher.finalize()),
                    });
                }
                atual = Some((kind.clone(), 0, Sha256::new()));
            }
            if let Some((_, contagem, hasher)) = atual.as_mut() {
                *contagem += 1;
                hasher.update(id.as_bytes());
                hasher.update(b"\0");
                hasher.update(estado.as_bytes());
                hasher.update(b"\n");
            }
        }
        if let Some((familia, contagem, hasher)) = atual.take() {
            familias.push(LinhaDoManifesto {
                familia,
                contagem,
                hash: format!("{:x}", hasher.finalize()),
            });
        }
        Ok(familias)
    }
}
```

```rust
/// Uma familia, como o hub a guarda.
#[derive(Debug, Clone)]
pub struct FamiliaDoManifesto {
    pub familia: String,
    pub contagem: i64,
    pub hash: String,
}

impl Hub {
    /// Troca o manifesto inteiro do aparelho.
    ///
    /// Apaga e regrava: familia que sumiu do aparelho tem que sumir do hub,
    /// e um `INSERT ... ON CONFLICT` deixaria a antiga para tras.
    pub fn guardar_manifesto(
        &mut self,
        dispositivo: &str,
        familias: &[FamiliaDoManifesto],
        visto_em: &str,
    ) -> Resultado<()> {
        let transacao = self.conexao.unchecked_transaction()?;
        transacao.execute(
            "DELETE FROM manifestos WHERE dispositivo = ?1",
            rusqlite::params![dispositivo],
        )?;
        for familia in familias {
            transacao.execute(
                "INSERT INTO manifestos (dispositivo, familia, contagem, hash, visto_em) \
                 VALUES (?1, ?2, ?3, ?4, ?5)",
                rusqlite::params![
                    dispositivo,
                    familia.familia,
                    familia.contagem,
                    familia.hash,
                    visto_em
                ],
            )?;
        }
        transacao.commit()?;
        Ok(())
    }

    /// O manifesto de um aparelho.
    pub fn manifesto_de(&self, dispositivo: &str) -> Resultado<Vec<FamiliaDoManifesto>> {
        let mut consulta = self.conexao.prepare(
            "SELECT familia, contagem, hash FROM manifestos WHERE dispositivo = ?1 \
             ORDER BY familia",
        )?;
        let linhas = consulta.query_map(rusqlite::params![dispositivo], |linha| {
            Ok(FamiliaDoManifesto {
                familia: linha.get(0)?,
                contagem: linha.get(1)?,
                hash: linha.get(2)?,
            })
        })?;
        let mut familias = Vec::new();
        for linha in linhas {
            familias.push(linha?);
        }
        Ok(familias)
    }
}
```

```ts
import type { AparelhoNaMalha } from "./types";

export type Alinhamento = {
  id: string;
  estado: "alinhado" | "atras" | "divergente";
  /** A frase curta que a linha mostra. Vazia quando não há o que dizer. */
  detalhe: string;
};

/**
 * Compara cada aparelho com ESTE, família a família.
 *
 * "Atrás" e "divergente" pedem ações diferentes, e é por isso que são estados
 * distintos: o primeiro se resolve sozinho na próxima rodada; o segundo é a
 * mesma contagem com conteúdo diferente, e aí a linha oferece reparo.
 *
 * Aparelho sem manifesto não é acusado de nada: ele é um M/OS que ainda não
 * atualizou, e marcá-lo de divergente ensinaria a ignorar o aviso.
 */
export function alinhamento(
  aparelhos: AparelhoNaMalha[],
  meuId: string,
): Alinhamento[] {
  const eu = aparelhos.find((aparelho) => aparelho.id === meuId);
  const referencia = new Map((eu?.manifesto ?? []).map((f) => [f.familia, f]));

  return aparelhos.map((aparelho) => {
    if (aparelho.id === meuId) {
      return { id: aparelho.id, estado: "alinhado", detalhe: "" };
    }
    if (aparelho.manifesto.length === 0) {
      return { id: aparelho.id, estado: "alinhado", detalhe: "sem manifesto" };
    }
    const dele = new Map(aparelho.manifesto.map((f) => [f.familia, f]));
    const atrasadas: string[] = [];
    const divergentes: string[] = [];
    for (const [familia, minha] of referencia) {
      const dela = dele.get(familia);
      if (!dela || dela.contagem < minha.contagem) {
        atrasadas.push(`${familia}: ${dela?.contagem ?? 0} de ${minha.contagem}`);
      } else if (dela.hash !== minha.hash) {
        divergentes.push(`${familia}: mesma contagem, conteúdo diferente`);
      }
    }
    if (atrasadas.length > 0) {
      return { id: aparelho.id, estado: "atras", detalhe: atrasadas.join(" · ") };
    }
    if (divergentes.length > 0) {
      return { id: aparelho.id, estado: "divergente", detalhe: divergentes.join(" · ") };
    }
    return { id: aparelho.id, estado: "alinhado", detalhe: "" };
  });
}
```
