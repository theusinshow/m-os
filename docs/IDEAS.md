# M/OS — Ideas

## 1. Propósito

Este documento funciona como a Inbox de ideias do próprio M/OS.

Aqui podem existir:

- possibilidades;
- desejos;
- experimentos;
- integrações;
- ideias incompletas;
- conceitos de longo prazo;
- soluções ainda não avaliadas.

Uma ideia estar presente aqui **não significa que será implementada**.

A função deste arquivo é permitir pensar livremente sem contaminar o Roadmap.

---

## 2. Regra

> **IDEAS.md não é ROADMAP.md.**

Nada deste arquivo deve ser tratado automaticamente como requisito.

Uma ideia só deve entrar no Roadmap quando houver justificativa real.

---

## 3. M/OS como cérebro digital

Ideia central:

M/OS funcionar como um lugar confiável para descarregar aquilo que normalmente permaneceria na cabeça.

O usuário pode desenvolver a confiança:

> Se é importante, provavelmente está no M/OS.

---

## 4. Entrada universal com Hermes

Ao abrir o M/OS, uma entrada de linguagem natural pode ser o elemento principal.

Exemplo:

> O que está na sua cabeça?

Usuário:

> Coloca na agenda e no Kanban que tenho que refatorar a navbar do projeto Escadas Minarum.

Hermes poderá interpretar e distribuir essa intenção para as partes corretas do sistema.

Quando Hermes estiver incerto, comunicar isso.

Exemplo:

> Acho que você está se referindo ao projeto Escadas Minarum.

Permitir correção.

---

## 137. AI memory boundaries

Usuário deve entender o que Hermes está usando como contexto.

Evitar sensação de comportamento misterioso.

---

## 138. Action log

Ações executadas por Hermes poderiam aparecer em histórico.

Exemplo:

```text
Hermes
Created Task "Refatorar Navbar"
Project: Escadas Minarum
```

Aumenta auditabilidade.

---

## 139. Undo Hermes

Quando possível:

> Hermes created Task.

`Undo`

---

## 140. Ask vs Act

Pode existir distinção implícita ou explícita entre:

> consultar

e

> executar.

Design deve tornar isso compreensível.

---

## 141. Natural language command chaining

Exemplo:

> Cria uma Task para refatorar navbar da Minarum, coloca para amanhã e cria uma Issue também.

Uma intenção, múltiplas ações.

---

## 142. App-specific Hermes tools

Cada App integrado poderá disponibilizar determinadas ações ao Hermes.

ChronoCAD:

- start timer;
- stop timer;
- get hours.

M-Finance:

- query summary.

GitHub:

- create issue;
- get PR status.

---

## 143. Permission levels por integração

Hermes pode ter:

- read;
- suggest;
- write with confirmation;
- autonomous reversible actions.

---

## 144. Personal automation recipes

No futuro, sequências repetitivas podem virar automações.

Exemplo:

Ao iniciar trabalho em um Project:

- abrir repository;
- iniciar ChronoCAD;
- abrir tools relacionadas.

---

## 145. Automation suggestions

M/OS poderia sugerir automação somente depois de identificar repetição real.

---

## 146. No automation theater

Não adicionar automações apenas para demonstrar inteligência.

Toda automação deve economizar esforço real.

---

## 147. Everything searchable

Princípio de longo prazo:

Se entrou no M/OS, deve haver uma maneira razoável de reencontrar.

---

## 148. Everything linkable

Elementos importantes podem eventualmente ser relacionados.

Sem exigir relações para tudo.

---

## 149. Everything actionable

Quando uma informação representa claramente uma ação, deve ser fácil agir sobre ela.

---

## 150. Final long-term idea

O estágio mais avançado imaginado para o M/OS é:

O usuário não precisa decidir qual software abrir, qual página navegar ou onde uma informação está.

Ele expressa sua intenção.

O M/OS utiliza seu conhecimento sobre:

- Projects;
- Tasks;
- Apps;
- Resources;
- tempo;
- integrações;

para encontrar o contexto correto e ajudar a realizar a ação.

Nesse estágio, o M/OS funciona realmente como a interface entre:

**pensamento**

e

**execução**.

# Catálogo de widgets da Home

Levantamento de 2026-08-14, a partir do desenho `M-OS Ideas - Hermes e Home v0.1`.

Cada entrada declara sua `Fonte` — de onde o dado viria. Isso não promove nenhuma delas
ao Roadmap: a regra da seção 23 do `ROADMAP.md` continua valendo, e a maioria depende de
integrações que ainda não existem.

O arranjo da Home continua em aberto: `1B` Capture-led, `1C` Temporal spine ou
`1D` Grade editável. A escolha muda quantos destes cabem.

---

## 151. Now / Current Context

Mostra em que você está trabalhando agora: projeto, task atual, tempo correndo, branch e
repo, com botão para retomar.

Talvez o widget mais importante depois da Capture.

Fonte: ChronoCAD + core + GitHub

---

## 152. Universal Capture

Não exatamente um widget, mas o elemento principal da Home. Texto, voz ou link salvo
instantaneamente na Inbox.

Fonte: core

---

## 153. Jarvis

Versão compacta do Hermes. Não um chat inteiro; algo como "pergunte ou peça algo".

Pode expandir para o Command completo.

Fonte: Hermes

---

## 154. Today

Tarefas, reminders e compromissos realmente relevantes para hoje. Sem calendário inteiro.

Fonte: core (exige agendamento) + calendário

---

## 155. Inbox Pulse

Quantas captures ficaram por processar, e quantas já passaram do ponto. Clicar abre a
Inbox.

Existe para evitar que a Inbox vire um cemitério.

Fonte: core

---

## 156. Continue Working

Últimos contextos usados, com um clique para restaurar.

Fonte: core (exige histórico de contexto)

---

## 157. Active Projects

Três a cinco projetos realmente ativos, com estado discreto, task atual e última
atividade.

Nada de grid gigante de cards.

Fonte: core

---

## 158. ChronoCAD / Work Timer

Projeto, task e tempo corrido, com Start, Pause e Stop.

No futuro pode alimentar cálculo real de tempo por projeto.

Fonte: ChronoCAD

---

## 159. M-Finance Snapshot

O mínimo que merece atravessar para o M/OS: saldo disponível, contas próximas, ou quanto
posso gastar.

Não duplicar o dashboard financeiro.

Fonte: M-Finance

---

## 160. GitHub Pulse

Somente o que exige atenção: PRs abertos, issues ligadas às suas Tasks, build quebrado.

Não mostrar commit por mostrar.

Fonte: GitHub

---

## 161. Project Pulse

Contextual ao projeto aberto: tasks abertas, quantas em Doing, último commit, captures
relacionadas.

Fonte: core + GitHub

---

## 162. Quick Apps

Ferramentas relevantes ao contexto atual. Em Web Design, Figma e Screenshot Tool; em
Engenharia, ChronoCAD e AutoCAD.

Fonte: App Registry

---

## 163. Recent Resources

Últimas referências salvas: site, biblioteca, imagem, tipografia.

Fonte: Library

---

## 164. Design Inspiration

Específico do Workspace Web Design: três ou quatro referências recentes, visualmente
maiores.

Seria um dos poucos widgets realmente imagéticos.

Fonte: Library

---

## 165. Waiting / Blocked

Coisas que dependem de alguém ou estão paradas: aguardando retorno do cliente, PR
esperando review.

Melhor que "tarefas atrasadas", que culpa em vez de informar.

Fonte: core

---

## 166. Someday / Ideas

Duas ou três ideias recentes, sem transformar tudo em Task.

Importante para quem gera projetos e ideias com frequência.

Fonte: core

---

## 167. Recently Captured

Últimas coisas jogadas no cérebro.

Serve para criar confiança de que sim, aquilo foi salvo.

Fonte: core

---

## 168. Recently Found

Itens acessados recentemente via Search. Permite voltar a algo sem pesquisar de novo.

Fonte: core (exige log de acesso)

---

## 169. Weekly Load

Visão simples: projetos ativos, Tasks em Doing e compromissos.

Não é produtividade gamificada; é alerta de sobrecarga.

Fonte: core

---

## 170. Project Cost / Value

Horas trabalhadas, valor recebido e valor por hora real de um projeto.

Fonte: ChronoCAD + M-Finance

---

## 171. Hermes Suggestions

Só quando houver algo realmente útil. Nada de sugestão constante.

Fonte: Hermes

---

## 172. Connections

Coisas relacionadas ao contexto atual. Abriu uma Task, mostra spec, PR, capture original
e resource relacionado.

Fonte: core (derivado)

---

## 173. System / M/OS Health

Muito discreto: salvo localmente, backup do dia, Hermes online.

Combina com a promessa de confiança do produto.

Fonte: core

---

## 174. Hermes Status

Estado da ponte com a VPS. Mostrar latência ou estado somente quando houver problema.

Fonte: Hermes

---

## 175. Quick Actions

Extremamente contextual. Dentro de um Project: nova Task, capturar, abrir repo, iniciar
trabalho.

Não uma coleção global de vinte botões.

Fonte: core
